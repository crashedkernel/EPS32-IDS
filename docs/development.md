# Development and verification

The sketch targets the Waveshare ESP32-S3-ETH. Use the Arduino settings and library versions in the [README](../README.md).

## Source layout

- `IntrusionMonitor/IntrusionMonitor.ino` contains the Arduino entry points, web routes, scan task, Ethernet and Wi-Fi setup, and LED handling.
- `DevicePolicy.h` manages whitelist state and timed acknowledgments.
- `OpenWrt*.h`, `RouterCommand.h`, and `GLClientStream.h` implement router discovery and SSH report parsing. The scan task owns the SSH session.
- `web/` contains the dashboard and shared browser assets. The Admin HTML is generated by the sketch from current settings.

Run `python3 tools/build_web_assets.py` after changing browser assets and commit the regenerated `IntrusionMonitor/WebAssets.h` with its sources. Never commit an actual router password, Admin password, Wi-Fi password, or backup from a deployed system.

## Compile

```sh
arduino-cli compile \
  --fqbn esp32:esp32:esp32s3:FlashSize=16M,PartitionScheme=huge_app,PSRAM=opi,USBMode=hwcdc,CDCOnBoot=cdc \
  IntrusionMonitor
```

## Release checks

1. Load the dashboard by Ethernet IP and through the setup AP. Check the inventory, search, sorting, clock, System Uptime, and Scan now.
2. Verify that Admin challenges unauthenticated requests. Sign in and open each section from the navigation. At desktop and phone widths, check that no controls or device columns are clipped. Toggle dark mode and text sizing.
3. On a test system, authorize and deauthorize one device, then exercise bulk selection, acknowledgment, and history clearing. Check the dashboard and RGB state after the next scan.
4. Save a configuration backup, change a test setting, and restore the backup. Confirm the expected restart, saved settings, and retained whitelist.
5. In GL.iNet mode, verify consecutive scans, disconnect Ethernet briefly, reconnect it, and confirm Watchtower resumes successful scans. Check the router logs to confirm the normal polling interval reuses the SSH login.
